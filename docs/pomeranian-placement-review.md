# ポメラニアンの配置調査

調査日：2026-10-29。対象：現行版 `index.html` / `home.js` / `home.css`。

## 結論

**大きなレイアウト変更なしで導入できる。ホームのメッセージ枠に小さく常設し、演習では回答後と完了時に登場させる構成が第一候補。**

スマホで新しいキャラクター専用枠を足す余裕は少ない。一方、PCの演習は中央の幅が520pxに制限されており、外側には余白がある。「画面全体に空きがない」わけではなく、端末と画面によって条件が異なる。

ホバーだけで登場させる方式はスマホで使いにくく、存在にも気づきにくい。ポメラニアン本体は見せて、追加の一言をタップ・キーボード操作で開く方式が適している。PCのホバーは補助にする。

## 確認した内容

- ローカルの現行版をブラウザで確認。幅320 / 375 / 768 / 1024 / 1440pxを計測。
- ホームの単語・文法、演習の単語・文法、文法の回答後、復習画面を確認。
- 既存素材一覧を表示し、通常・応援・振り返り・達成などのSVGを確認。
- 学習記録のない確認用環境を使用。公開版や普段の学習記録は変更していない。
- ポメラニアンを実際に組み込んだ状態の検証は未実施。以下の推奨サイズは設計の目安。

## 配置候補の比較

| 候補 | 目安サイズ | 必要な調整 | 評価 |
|---|---|---|---|
| ホームのメッセージ枠の左 | 40〜48px | 既存のメッセージアイコンを置換。連続日数バッジは文面側に残す。文字の折り返しに合わせて枠の高さを少し調整 | **第一候補。案内役として自然で、常に会える** |
| 回答後の正誤表示 | 32〜40px | 既存の判定アイコンを置換。新しいメッセージを重複表示しない | **第一候補。解いたことへの反応として意味がある** |
| 演習の完了カード | 80〜112px | 結果の上に達成ポーズを追加 | **大きく見せる場所として適している** |
| PCの演習欄の外側 | 80〜120px | 広い画面だけ表示。目安は1200px以上。中央欄と切り離して配置する | 常時表示を重視する場合の追加案 |
| 教材カードのアイコン | 24〜32px | 教材ごとの既存アイコンを置換 | 省スペース。ただし小さくて表情が伝わりにくい |
| 全画面共通の右下フロート | 48〜64px | 「次へ」、教材一覧、シートとの衝突回避が必要 | スマホの第一候補にはしない |
| ホバー時だけ表示 | 可変 | スマホ用のタップとキーボード操作も必要 | 補助演出向き。キャラクターの主な登場方法には弱い |

## おすすめの体験

1. **ホーム**：メッセージの左に通常ポーズ。今ある案内文をキャラクターの一言として使う。
2. **回答中**：スマホでは新たな常設枠を作らず、問題に集中できる構成を保つ。
3. **回答後**：正解なら応援、不正解なら一緒に考えるポーズ。既存の正誤表示に組み込む。
4. **連続正解・目標達成**：既存の回答後表示の中で表情を変える。別のポップアップを重ねない。
5. **演習完了**：達成ポーズを大きく表示する。

「ずっと一緒にいる感じ」を強めたい場合は、PCだけ演習欄の横に常設する。スマホはホームの常設と回答後の登場を基本にする。

## 実装時に確認すべき接続箇所

- `home.js` の `renderHomePage()`：メッセージ枠と教材アイコン。
- `home.css` の `.home-message-bar`：横並びと文字の折り返し。ポメラニアンのためにページ全体の余白を一律に詰める必要はない。
- `index.html` の `#duo-banner` / `showDuoBanner()`：既存の正誤バナーは **Duolingoテーマ限定**。全テーマでポメラニアンを使う場合、表示条件とテーマ別の色を調整する必要がある。
- スマホの通常テーマでは、既存カード内の正誤表示とポメラニアンをまとめる案も比較する。新しい独立バナーを足すと、解説の見える高さが減る。
- `index.html` の単語・文法の完了カード：達成ポーズの追加場所。
- `#app` は `overflow: hidden`。PCの外側に置く場合、単に中の画像をはみ出させると切れる。外側に専用の配置領域を設ける必要がある。
- `next/companion.mjs` は試作版のしおり型キャラクター。現行版の表示には接続されていない。ポメラニアン素材も現行版からの参照は見つからなかった。
- `assets/pomeranian/` は調査時点でGit未追跡。実装時には素材を含め、オフラインの初回保存対象として `sw.js` も調整する。
- 常時の揺れ・跳ねは控え、反応の瞬間だけ動かす。動きを減らす端末設定を尊重する。
- 一言を開く操作を付ける場合、表示サイズとは別にタップ領域とキーボードフォーカスを確保する。

## 調査の限界と次の確認

サイズの組み合わせ、文字拡大、長い不正解表示、ソフトキーボード表示、全テーマの組み込み後検証は未実施。特に小型スマホでは、キャラクター追加後も「つづきから」「次へ」と解説が操作できることを確認する必要がある。

今回は調査のみ。アプリのコード・公開内容は変更していない。実装する際は、配置と変更ファイルのプランを提示して合意してから進める。
