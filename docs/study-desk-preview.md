GitHub Pagesのサブディレクトリで再読み込みしても404にならない構成。

## 学習記録の境界

試用版が書き込むlocalStorageキーは **`toeic_next_v1` だけ**。
初回に従来版の成績、苦手、学習済み記録を読み取り、試用版の形式へコピーする。
復習の削除記録（`toeic_weak_deleted`）を考慮し、解除済みの苦手を復活させない。
旧形式の単語記録は既存版と同じく4モードへ展開する。

コピー後は、従来版の記録を再取り込みしたり、上書き・削除したりしない。
Google Driveの認証設定、同期フラグ、クラウドファイルは利用しない。
同期APIも認証用スクリプトも読み込まない。Obsidianへの送信も行わない。

従来版の途中の演習と出題設定は引き継がない。
試用版の中では、出題順、選択肢、回答、現在位置を保存して再開する。
教材内容が変わった場合は古い演習を再開せず、成績と苦手記録を保持して教材選択へ案内する。
壊れた記録や未知の保存形式は上書きせず、保存できない状態を画面に表示する。
別タブの変更を検出した場合も上書きを停止する。

試用版の記録はGoogle Drive・従来版・別端末に反映されない。
設定から試用版専用JSONを書き出し、同じ設定画面で取り込める。
取り込み時は現在と反映後の件数を表示し、「統合」または「置換」を選んで明示的に確定する。
従来版の `toeic-drill` 形式1〜5と `toeic_practice_backup` も読み込み可能。
試用版からの書き出しは専用形式なので、従来版へ取り込む用途ではない。
従来版からは学習記録を取り込み、出題設定と演習の続きは引き継がない。
試用版のバックアップを置換復元すると、テーマ・効果音設定・互換性のある演習の続きも復元する。
形式番号のない初期試用版の書き出しも読み込める。

統合では学習済みを集合としてまとめ、成績は正解・不正解それぞれの最大値を採用する。
同じファイルの繰り返し取り込みでは成績を重複加算しない（各端末の全回答を厳密に合算する方式ではない）。
苦手の更新時刻と削除記録で、克服済みの問題が古いバックアップから復活するのを防ぐ。
教材にない項目も記録として保持し、確認画面でその旨を表示する。

復元前の状態を同じ保存キー内に1回分だけ保持し、再読み込み後も取り消せる。
取り消しも件数と説明を確認して確定する。復元後の演習や設定変更も戻ることを画面に明示する。
容量不足や別タブの更新で復元に失敗した場合、メモリ内の記録も保存済み記録も変更しない。
取り消し用の過去状態はバックアップへ書き出さず、履歴が再帰的に増えないようにしている。

## テーマとUIの継承（2026-10-28）

- 従来の7テーマ：和モダン、Duolingo、ネイビー、Quizlet、フォレスト、チャコール、セピア。
- Study Desk：ライトと夜の2種類。計9テーマの見本付き選択画面。
- 従来版の `light` は試用版では `sepia`。試用版の既存 `light` はStudy Deskのまま維持する。
- 新規利用時のみ従来の選択テーマをコピー。既に試用版を利用中なら、その選択を維持する。
- 演習中のテーマ変更は問題・回答・進捗に影響しない。
- Duolingo風の立体ボタン、丸い書体、太い進捗バー、画面下部の判定バナー、効果音を追加。
- 連続正解とXPは今回の演習の回答から計算。1正解10XP。再読み込み・見直し・切り替えで加算しない。
- 効果音は設定で停止可能。音が使えない環境でも判定表示と操作を維持する。
- ホームに成績の概要、教材の背表紙を模した一覧、テーマへの入口を追加。
- 演習の操作を画面下部に固定し、内容末尾とキーボードフォーカスには余白を設ける。
- Duolingoではボタンの沈み込み、回答直後の短い反応、進捗バーの伸びを統一。動きは新しい回答のときだけ発生し、再読込・見直し・テーマ変更では再生しない。動きを減らす端末設定では停止する。
- 3・5問、および10問ごとの連続正解を下部に表示。不正解時は正しい答えを表示し、長い答えはバナー内でスクロールできる。固定欄の高さに合わせて本文末尾の余白も調整する。
- 終了画面ではオリジナルの星バッジと、正答数・獲得XP・最高連続正解を表示。数値は保存済みの回答から計算し、報酬を重複加算しない。
- 教材一覧は単語・文法のセクションに分け、Duolingoでは教材アイコンも立体的なバッジとして表示する。

## 画面幅に合わせた操作設計（2026-10-28）

スマホとPCは同じURL・採点・記録・テーマ・バックアップを共有する。
基本の伸縮と配置はCSS、絞り込みの開閉・適用・取り消しはJavaScriptで扱う。

- 768px以下：ホーム・復習・設定のナビを下部へ。ホームでは教材を成績より先に置き、カードをコンパクトにする。
- 出題設定は教材・問題数・答え方・適用中の条件を表示し、対象件数と開始ボタンを下部に固定する。
- 詳細条件は「絞り込み」で開くネイティブdialogに集約する。候補部分だけがスクロールし、閉じる・解除・適用はパネル内に残る。
- パネルでは設定のコピーを編集し、「適用」だけが出題設定に反映する。閉じる・Esc・別画面への移動は未適用の変更を取り消す。解除も適用するまで確定しない。
- 幅変更時も適用済み条件と編集中の条件を保持する。開いたパネルは広い画面でも閉じず、明示的な適用か取り消しを待つ。入力欄を重複配置しない。
- 769px以上：基本設定と詳細条件を左右に配置する。長い条件一覧は内部スクロールでき、複数選択しても位置を保つ。ここでの変更は即座に反映する。
- 演習は900px以下で縦並び、より広い画面では問題と解説を左右に並べる。768px以下では共通ヘッダーを省き、演習の戻る・進捗・テーマに集約する。
- タイプ回答の入力欄・答え合わせボタンにフォーカスがある間、スマホの固定操作バーを畳み、入力操作を優先する。
- ホームの「10問から始める」は金の文法から直接開始する。未完了の演習があるときは「続きから」を表示する。
- 設定のテーマ見本を展開式にし、バックアップへの移動を短くする。9テーマと効果音設定は維持する。

検証はChromeの隔離プロファイルで行う。320〜1440px、横向き、200%文字、幅変更中の選択保持、パネル内のフォーカス、0件の開始防止を確認する。
ソフトウェアキーボードについては画面の高さを縮めたテストまでで、iOS/Androidの実機での表示は別途確認が必要。

## オフラインと従来版への復帰

従来版へはホーム・出題設定・復習・設定の画面上部のリンクから戻れる。スマホの演習中はホームに戻ってから開く。学習記録の移行操作は不要。
試用版のService Workerは `/next/` スコープのみを制御する。
従来版のService Workerを登録解除したり、キャッシュを削除したりしない。

現行の親Service Workerは有効化時に `toeic-drill-v1` 以外のキャッシュを削除する。
そのため試用版も同名キャッシュを使用するが、保存するURLキーはすべて
`/next/__offline__/` 以下に分離する。教材データも専用キーへ保存するので、
従来版のHTML・教材のキャッシュエントリーは変更しない。
将来、親Service Workerのキャッシュ名や削除方針を変える場合は、この互換性を再確認する。

初回の教材読み込み・キャッシュ作成にはオンライン接続が必要。
ブラウザによるサイトデータの消去は、オフライン教材と端末内記録の両方に影響する。

## ローカルで確認

作業フォルダで以下を実行し、`http://127.0.0.1:8766/next/` を開く。

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

localhostとGitHub Pagesの保存領域は別なので、ローカルプレビューには本番の記録は現れない。
コピー動作はテストの仮の記録で検証する。

```sh
node --test tests/next-core.test.mjs tests/next-backup.test.mjs
# Playwrightが利用可能な環境。インストール済みGoogle Chromeを一時プロファイルで使用。
NODE_PATH=/path/to/node_modules node tests/next-browser.cjs
```

確認対象: 初回コピーと以降の分離、破損記録、保存失敗、複数タブ、
文法と単語4モード、複数章選択、解答後の再読込、前の問題への移動、
二重採点防止、10問完了と誤答再演習、復習一覧、
375/768/1024/1440px、横向き、文字拡大、ダーク表示、reduced motion、
親Service Worker有効化後のオフライン操作、外部通信がないこと。
追加で全テーマの主要文字コントラスト、テーマ変更による演習保持、
DuolingoのXP保持、ファイル選択だけで記録が変わらないこと、
書き出し→置換復元→再読み込み→取り消し、不正ファイル拒否を検証する。

## Google Drive連携の次段階（設計のみ・未実装）

従来版のクラウドファイル `toeic-drill-backup.json` は読み書きの対象にしない。
試用版用に `toeic-study-desk-preview-backup.json` を別ファイルとして扱う。
試用版の連携設定も専用保存領域内に保持し、従来版の接続フラグは引き継がない。
ユーザーが試用版で「接続」を選ぶまで、認証やクラウドへの送信を開始しない。
アクセストークンはメモリ内だけで扱い、JSON書き出しには含めない。

初回接続時はクラウドの有無を確認し、端末とクラウドの件数を表示して取り込み方法を選ぶ。
最初は手動同期から始め、競合時の説明と復元を検証してから自動同期を検討する。
同時更新、期限切れ認証、オフライン、削除記録の伝播、失敗時の巻き戻しを追加テストの対象にする。
設定保存・途中位置の保存だけで同期が再発火し続けないよう、学習記録の変更を区別する。
公開前にはテスト用Googleアカウントで従来版のファイルが不変であることを確認する。

Obsidian連携も今回の追加対象には含めない。設定画面で未対応であることを明示する。

## 公開の手順（承認後に実施）

1. 最新の公開ブランチとの差分を再確認し、追加対象が `next/`、試用版テスト、本書のみであることを確認する。
2. 復元タグと作業ブランチをpushし、追加内容をレビューする。
3. 承認後、`main` に取り込む。Pagesは `main` のルートを公開している。
4. 従来URLと `/next/` の両方を確認する。最初は従来画面への告知リンクも追加しない。
5. 共有は試用URLから始め、利用者が任意に選ぶ。

利用者が戻す操作は「従来版へ」を押すだけ。
試用版自体の公開を取り消す必要がある場合は、この追加変更をrevertする手順を確認してから実施する。
履歴の強制巻き戻しや従来版の記録削除は不要。
公開停止後もインストール済みService Workerのキャッシュは端末に残り得るため、
配信停止を即時・完全な無効化とみなさない。必要な場合は試用版専用の停止画面を配信する。
