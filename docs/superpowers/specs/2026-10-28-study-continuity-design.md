# 学習を続けやすくする6機能 — 設計案

状態：レビュー用。実装・公開は未着手。
対象：`/next/`。基点：`be73cca`。2026-10-28。

## 目的

「次に何をするかが分かる」「設定を繰り返さず始められる」「復習の成果が分かる」を実現する。
ホームを長くする機能追加を避け、既存の教材カード・演習結果・設定を活用する。

## 共通制約

- 従来版の `index.html`・`data/`・`sw.js` と従来版の保存キーは変更しない。
- 試用版の保存キーは `toeic_next_v1` の1つだけを使う。
- GitHub Pagesで動く静的構成を維持し、外部サービス・外部依存・外部通信を追加しない。
- 全9テーマ、320〜1440px、200%文字、キーボード操作、動きを減らす設定に対応する。
- 公開サイトへの反映は、ローカル検証と利用者の確認を経て別途行う。

## 1. 前回の条件で再開

教材ごと（文法・単語＋教材ID。`all`も独立）に、最後に通常演習を開始した設定を保存する。
対象は章・品詞・番号・追加日・出題フィルター・問題数・答え方。
設定画面を触っただけ、パネルをキャンセルしただけでは「前回」を変更しない。

ホームの優先順位：
1. 未完了セッションがあれば「続きから」。
2. 前回条件があれば、教材名と条件の要約を添えた「前回の条件で開始」。
3. 初回は現在の「金の文法を10問」。

教材を開くとその教材の条件を初期表示する。条件変更は現在の設定・絞り込みパネルから行う。
個別復習・間違い直し・今日の復習は通常演習の設定を上書きしない。
教材更新で選択範囲が一部消えた場合は、広い範囲に黙って変更して開始しない。
設定画面で「教材更新により一部の条件を見直してください」と案内し、残った条件を確認して開始する。
条件が有効でも対象0件なら、設定画面へ移動して理由と解除操作を示す。
設定画面から「標準に戻す」で教材の通常設定に戻せる。開始した時点で保存する。

## 2. 教材ごとの進捗

既存カード内に小さなバーと「学習済み 30 / 160問・未学習130問」を表示する。
正解率や習得度とは区別する。間違い・「わからない」も一度取り組んだので学習済みに含む。
文法は既存の `grammarSeen` を教材の問題IDに照合する。
単語は4モードの `seenWords` の和集合を使い、カードに「いずれかのモードで回答済み」と説明する。
同じ単語の教材内重複は現行の出題処理と同じ語キーで1語と数える。
複数教材に同じ語があれば各カードでは学習済みになる。教材合計を全体の学習語数として足さない。
不明な問題ID・削除済みの語はカードの分母・分子に含めない。古い記録自体は削除しない。

## 3. 今日の目標

初期値10問。設定で「なし・5・10・20・30問」を選べる。
ホームに1行「今日 6 / 10問」と小さな進捗表示を置き、押すと目標・学習日カレンダーを開く。
新規の回答確定を1問と数える。正誤、カードの自己判定、わからないを含む。
同じ問題でも新しい演習で解き直す行為は1問と数える。同一セッションでの再表示・再採点は加算しない。
初めて目標を越えた回答の直後だけ、小さく「今日の目標達成」を表示する。
ページ再読み込み・復元・目標変更だけでは達成演出を再生しない。
達成時も演習を止めず、答え合わせと次へを優先する。
日中の目標変更は今日に反映し、昨日以前の目標は変えない。「なし」の日は目標達成マークを付けない。

## 4. 学習日数とカレンダー

日別記録は導入後に回答した日から開始する。過去の通算回答数から日別履歴を推測しない。
日付は回答時点の端末のローカル日付。保存済みの日付は旅行・時差変更で書き換えない。
1問以上回答した日は学習日。学習日と目標達成日は文字・印でも区別する。
表示は累計学習日数と月単位カレンダー。前月・翌月ボタンを用意し、未来月には移動しない。
本日未学習でも昨日まで続いていれば、その連続日数を表示する。空白日があれば連続は切れるが累計は保持する。
カレンダーはホームに常時展開せず、今日の目標行と設定から開く。
アプリを開いたまま日付が変わる場合は、次の回答・画面復帰・日付変更タイマーで表示を更新する。

## 5. 間違い直しの成果

各回答に、回答直前に苦手だったか `wasWeak` と、その回答で間隔復習を完了したか `graduated` を記録する。
終了画面に「苦手を3問復習できました」を表示する。対象は今回回答した既存の苦手のうち正解した問題。
「克服」は既存の間隔復習ルールで苦手から削除された場合にだけ使う。
即日解き直しの正解で、間隔復習の予定を早めたり苦手を削除したりしない。
全問不正解・途中終了・0件のケースで、復習できた／克服したという誤った表示をしない。
旧セッションの結果にはこの情報がないため、過去の弱点状態を推測した成果は表示しない。

## 6. オリジナルの案内役

本のしおりをモチーフにした小さなキャラクター。公式キャラクター・名称・素材は使用しない。
ローカルSVGとCSSで通常・応援・振り返り・達成の4状態を用意する。
設定は `auto`（Duolingoのみ、初期値）・`on`（全テーマ）・`off`。
登場箇所は回答後の既存バナーと終了画面。問題文・選択肢・次へボタンには重ねない。
新しい通知枠は作らず、正誤・目標・復習の既存メッセージを案内役と共有する。
優先順位は正誤の内容 → 目標達成 → 連続正解。文字を重ねず、補助メッセージは1つに絞る。
同じ演習の見直しや再読み込みで再アニメーションしない。常時跳ねる動き、画面全体の演出、音の追加は行わない。
SVGは装飾として読み上げ対象外にし、意味は隣接テキストで伝える。

## 保存形式と互換性

保存キーは同じまま、ローカル `schema: 2`、試用版バックアップ `format: 2` にする。
ローカル旧schema1は読み込み時に検証・移行し、保存が成功するまで元文字列を保持する。
未知の将来版・壊れたデータは書き換えず保存停止を表示する。
旧アプリに新形式を読ませた場合も、対応していない旨を表示して書き換えない既存の保護を維持する。
旧schema1の復元取り消しスナップショットも1段だけ同じ移行を行う。

追加データ：

```js
preferences: {
  dailyGoal: 10,             // 0, 5, 10, 20, 30
  companion: 'auto',        // auto, on, off
  recentPreset: null,       // 例: grammar:kin
  presets: {}              // 教材キー → 検証済みの既存config
},
activity: {
  startedOn: '2026-10-28',  // 導入日のローカル日付
  days: {}                 // YYYY-MM-DD → { answers: 非負整数, goal: 0|5|10|20|30 }
}
```

当日の回答数は `recordAnswer` がtrueを返す採点経路だけで増加する。
日別の正誤内訳や全回答イベントは保存しない。現要件に不要な履歴膨張を避ける。
セッション回答の `wasWeak` / `graduated` は任意のboolean。旧データでは未定義を維持する。

### バックアップ

新しい形式の書き出し・読込・置換・統合・取り消しをセットで対応する。2MB上限は維持。
試用版format1・版なし、従来版1〜5からも復元可能。新項目を持たないバックアップは既存記録だけを扱う。
統合では現在の設定を優先し、学習日の集合をまとめる。同じ日の回答数は大きい方、目標は現在の値を優先する。
これは既存バックアップと同様の保守的な統合であり、複数端末の同日回答数を厳密に合算する仕様ではない。確認画面に明記する。
新形式の置換は設定・日別記録も置換する。旧形式の置換では現在の設定を保ち、日別記録を空にする旨を確認画面に出す。
取り消しは記録・設定・日別記録をまとめて戻す。復元そのものでは目標達成の演出を起こさない。

1. 保存形式・移行・バックアップを作る。
