# iOS 限定の「画面の枠」を全テーマに広げる — 設計

作成日: 2026-11-04 / 状態: 設計の合意待ち（実装前）
前提の設計書: `2026-11-04-ios-wide-layout-design.md`（iOS テーマの横画面版。実装・公開済み）

## 目的

今は iOS テーマだけにある次の機能を、全テーマ（ink / duolingo / navy / quizlet / forest / nordic / light / ios）で使えるようにする。

1. **画面の下に浮いたタブバー**（幅 1000px 未満）と、そのスワイプ格納・見出し行のスワイプ格納・戻すつまみ
2. **横画面版**（幅 1000px 以上）: 左のサイドバー、中央寄せの本文、右の絞り込みパネル

見た目の色は、各テーマのものを使う。iOS のガラスの質感・青・ボタンの形・大きな見出し・ SF Symbols 風でないアイコン以外の装飾は、iOS テーマに残す。

## 合意したこと（会話での決定）

| 項目 | 決定 |
|---|---|
| 見た目 | 各テーマの色で（iOS のガラス風には統一しない） |
| 他テーマのナビの位置 | 下の浮いたタブバーにそろえる（上のバーはやめる） |
| 横画面版・縦画面のスワイプ格納 | 全テーマで使う |
| ファイル名 | 中身に合わせて変える（下の「名前の変更」。ユーザーの了解が必要） |

## 設計

### 1. ファイルの構成と読み込み順
| 今 | 変更後 | 役割 |
|---|---|---|
| `css/theme-ios-wide.css` | `css/shell.css`（名前を変える） | **全テーマ共通**の画面の枠。下のタブバー、格納・つまみ、横画面版（サイドバー・パネル・本文の幅）。 |
| `css/theme-ios.css` | 同名（中身を減らす） | iOS の見た目だけ。ナビの構造（位置・形・タブの並び）と格納の構造は shell.css に移す。ガラスの背景・ぼかし・影・青い選択色は残す。 |
| `js/ios-chrome.js` | `js/shell-chrome.js` | スワイプ格納（タブバー・見出し行・つまみ）。`isIos()` の条件を外して全テーマで動かす。 |
| `js/ios-wide.js` | `js/wide-layout.js` | 横画面の絞り込みパネルの開閉と記憶。`isIos()` の条件を外す。 |
| `tests/ios-wide.test.js` | `tests/shell.test.js` | 全テーマを対象にしたテスト。 |

- 読み込み順: `home.css` → `css/app.css` → **`css/shell.css`** → `css/theme-ios.css`（iOS の見た目が、共通の枠の上に重なる）。
- shell.css の選択子は `[data-theme]`（どのテーマにも当てはまる）で書く。詳細度が `[data-theme="ios"]` と同じなので、`home.css` / `app.css` の既存の指定に勝ち、iOS 専用の指定は後ろの theme-ios.css で上書きできる。
- `index.html` の link / script と読み込み順のコメント、`sw.js`（ASSETS。キャッシュ名を `v8` に）、`upload.py`（FILES）を更新する。古いファイル（`theme-ios-wide.css`、`ios-chrome.js`、`ios-wide.js`）は、リポジトリから削除する。公開先に残る古いファイルは、使われなくなるだけで害はない。

### 2. クラス名と記憶のキー
iOS 専用の名前のままだと紛らわしいので、次のように変える。

| 今 | 変更後 |
|---|---|
| `ios-nav-stowed` / `ios-top-stowed` | `nav-stowed` / `top-stowed` |
| `ios-grabber`、`-bottom` / `-top` / `-footer` | `shell-grabber`、`-bottom` / `-top` / `-footer` |
| `ios-filter-panel-open` | `filter-panel-open` |
| localStorage `toeic_ios_nav_stowed` / `toeic_ios_top_stowed` | `toeic_nav_stowed` / `toeic_top_stowed` |
| localStorage `toeic_ios_filter_panel` | `toeic_wide_filter_panel` |

端末に覚えさせた「格納している」「閉じている」の状態は、引き継がない（もう一度操作すれば覚え直す）。

### 3. 幅 1000px 未満（全テーマ）: 下の浮いたタブバー
- 今の iOS と同じ配置（左右 16px、下から 8px とセーフエリア、丸いカプセル、ブランドは隠す）、同じタブの並び（アイコンの下に文字、高さ 52px）。`#app` の下の余白（`--ios-tab-space`）も同じ。
- 色は、各テーマの変数を使う。
  - バーの背景 `--top-sheet-bg`、枠 `1px solid --top-sheet-border`、影は控えめな黒（透明度 0.22）。
  - 選択していないタブ `--text-muted`。選択中のタブは、各テーマの既存の `.top-page-tab.active`（アクセント色の塗り。`light` と `duolingo` の既存の指定も、そのまま効く）。
- タブのアイコンは、今 iOS にある線画（home / pencil / arrow.clockwise / gearshape の近似）を、全テーマ共通にする（文字色 `currentColor`）。
- スワイプ格納・見出し行の格納・つまみ（演習画面の下の情報行の真上を含む）は、今の iOS と同じ動き。CSS は shell.css に移す。
- ナビが上にあった分の高さが空くので、他テーマの本文は、その分広がる。

### 4. 幅 1000px 以上（全テーマ）: 横画面版
`2026-11-04-ios-wide-layout-design.md` のとおり（左のサイドバー 240px、本文の最大幅 演習 640px・復習 720px・設定 640px・ホーム 1080px、右の絞り込みパネル `clamp(320px, 30vw, 380px)` で画面の高さいっぱい、最初は開いて開閉を覚える、チップは折り返し、「この条件で解く」は下に固定）。違いは次の 2 点だけ。
- 見た目の色は、各テーマの変数（サイドバーの背景 `--top-sheet-bg`、枠 `--top-sheet-border`、パネルは既存の `.top-sheet` の色）。
- 幅 1000px 以上では、タブバーの格納とつまみは無効（サイドバーは常に出す）。

### 5. iOS に残すもの（theme-ios.css）
ガラスの背景・ぼかし・影（ナビ、シート、パネル）、青い選択色、枠なしのナビ、丸いカプセルのボタン、セグメント、Large Title、設定の Inset Grouped、ホームのカード、線画の絵文字アイコン（`.ico`）。これらは今のまま、iOS だけ。

## 確認する方法
1. `tests/shell.test.js`（旧 ios-wide.test.js を拡張）を、全 8 テーマで実行する。
   - 幅 1000px 以上: サイドバーとパネルが出る、開閉と記憶、ホームの「範囲を指定」、ナッジ、`localStorage` が使えない場合（既存のテストを全テーマに）。
   - 幅 1000px 未満: 下のタブバー、スワイプで格納（下へ 36px 以上で格納、短いと格納しない）、つまみで戻る、見出し行の格納、格納の記憶。
   - テーマを切り替えたとき、状態が混ざらない（iOS から他のテーマへ、など）。
2. 検証用のスクリプト（`ios-isolation.cjs`）は、「iOS の CSS があってもなくても、他テーマの見た目が同じ」と「テーマを往復して元に戻る」を確かめるために残す。「他テーマでは格納が働かない」という項目は、新しい仕様に合わせて直す。
3. 既存の Python / Node のテスト（`practice-chrome` など）。ナビが上にあることを前提にした測定があれば、新しい配置に合わせて直す。
4. ブラウザで、全 8 テーマを幅 390px と 1280px で目で確かめる（とくに `light` と `duolingo`）。
5. iPhone / iPad / Mac の実機での見え方は、公開後に本人が確認する。

## 注意点・リスク
- **他テーマの狭い画面の見た目が大きく変わる**（上のバー → 下の浮いたバー）。これはユーザーが選んだ変更。変更前に戻したいときは、shell.css の読み込みを外せば戻る。
- 他テーマの既存のテストや CSS が、「ナビが上にある」前提で書かれている箇所があり得る。実装中に洗い出して、新しい配置に合わせる。
- 各テーマで、バーの背景が本文の背景に埋もれないか（コントラスト）を、目で確かめる。
- `:has()` を使う（前の設計と同じ。古い Safari では、演習画面の下の余白が従来どおりになるだけ）。
- 名前の変更で、公開先に古いファイルが残る。`sw.js` のキャッシュ名を上げて、古いキャッシュを捨てさせる。
