# 現行版へ Study Desk（`/next/`）の機能を移植する — 設計案

状態：設計案（レビュー待ち）。2026-10-29。
対象：公開中の現行版（`index.html` ＋ `home.js` ＋ `home.css`）。`/next/` は読み取り専用の参照元で、変更しない。

## 目的

現行版の見た目・3画面構成・Google Drive 同期はそのままに、`/next/`（chat 版）で作った機能のうち
有用なものを現行版へ移植する。あわせて、PC の広い画面でも使いやすい配置にする。

## 決定事項（ユーザー確認済み）

- 土台は現行版。見た目、ホーム・演習・設定の画面構成は意図的なものなので維持する。
- 画面は「復習」を足して 4 つにする。
- 新しいコードは別ファイルに分けてよい。ビルド処理は足さない。
- 絞り込みの挙動は現行のまま（タップで即反映）。chat 版の「適用で確定」方式は採用しない。
  足すのは対象件数の表示だけ。
- 既存の記録は消さない。`/next/` は試しただけで、そこに貯めた記録の引き継ぎは不要。
- **演習画面の PC 向けレイアウトは今回やらない。後で別途進める。**

## 範囲と順序

1 段階ずつ「実装 → 確認 → 公開」で進める。公開（`main` への push）は段階ごとに利用者の確認を取る。

| 段階 | 内容 |
|---|---|
| 1 | 絞り込みに「対象 N 問」を表示 |
| 2 | ホーム画面の PC レイアウト |
| 3 | 今日の目標とカレンダー |
| 4 | 4 つ目の画面「復習」 |
| 5（任意） | 9 テーマ化、しおり型の案内役。今回の計画では着手しない |

## 段階 1：絞り込みの対象件数

現状、絞り込みボタンの数字は「適用中の条件の数」で、対象の問題数ではない（`updateFilterSummary`）。

- 絞り込みシートの「この条件で解く」ボタンのラベルに「（対象 N 問）」（単語は「N 語」）を付ける。条件を変えるたびに更新する。
- 件数を出すのは絞り込みシートだけ。演習画面は既存のフッターの進行表示のままにする。
- 対象が 0 件のときはボタンの近くに理由を示す。既存の「条件に合う…がありません」の表示は変えない。
- 件数は既存の出題プールの絞り込み関数（`applyFilters` / `applyGrammarFilters` が使う判定）と同じ判定で数える。
  件数用に別のロジックを作らない。

## 段階 2：ホーム画面の PC レイアウト

現状は 1440px でも中央の細い縦一列（幅は約 480px 相当）。ホームだけ広い画面向けにする。

- 幅の目安：約 1024px 以上で 2 カラム。それ未満は現行の 1 カラムのまま。
  - 左：メッセージ枠、単語/文法の切り替え、学習中の参考書カード、苦手問題バー
  - 右：今日の目標（段階 3 で追加）、他の参考書の一覧
- 「他の参考書」は PC では内側スクロールをやめ、一覧としてそのまま並べる。スマホでは現行の内側スクロールを維持する。
- 色、カード、角丸などの見た目は現行のテーマ変数を使い、新しい配色を足さない。
- 演習画面と設定画面は今回の範囲外。現行の幅のまま。ヘッダーのナビはホームに合わせて広げるが、
  演習・設定の中身の幅は変えない。幅の制限をページごとに分けて持たせる。
- 確認する幅：320 / 375 / 768 / 1024 / 1440px、文字拡大 200%。

## 段階 3：今日の目標とカレンダー

### 置き場所

- ホームのメッセージ枠の下に独立した 1 行「今日 3 / 10問」と細い進捗バーを置く。PC では右カラムの上。
- タップでダイアログを開き、目標の変更と月カレンダーを表示する。カレンダーはホームに常時表示しない。

### メッセージ枠との共存（`home.js` の `buildHomePraiseMessages`）

メッセージ枠のロジックと切り替え操作はそのまま残す。変更は次の 2 点だけ。

- 目標を設定しているときは、目標行を「今日の解答数」の表示とする。
  1 番目のメッセージは「今日はすでに N 問解答」の部分を除き、連続日数と正答率だけにする。
  目標が「なし」のときは現行のメッセージのまま。
- 目標を達成した日は、ローテーションに「今日の目標達成」を 1 つ追加する。

ペース計測、即答バッジ、フッターの平均ペース表示、連続日数の計算は変更しない。

### データ

- 既存の `toeic_daily_activity_v1`（`days[YYYY-MM-DD] = { a, c, fast, sec }`）を拡張し、その日の目標 `g` を任意で持たせる。
  `g` が無い古い日は「目標なし」として扱う。既存のフィールドは変更しない。
- 目標の設定値（なし・5・10・20・30問、初期値 10）は新しいキー `toeic_prefs_v1` に保存する。
- 目標の達成は、その日の `a >= g` で判定する。昨日以前の目標は変更しない。
- 日付は回答時の端末のローカル日付。過去の通算回答数から日別の履歴は推測しない。
- 日付が変わったとき（アプリを開いたままの場合を含む）に表示を更新する。

### バックアップ

- バックアップ形式を 5 から 6 に上げ、日別記録 `toeic_daily_activity_v1` と `toeic_prefs_v1` を含める。
  `BACKUP_MIGRATIONS` に 5→6 の変換を足す。新しい項目は空で補わず、版だけ上げる（無い項目は「今のまま」。空で補うと、形式 5 以前のファイルを上書き復元したときに日別記録が消えるため）。形式 1〜5 のファイルは従来どおり読み込める。
- 統合では、日別記録は同じ日の `a` の大きい方を採用し、目標は現在の値を優先する。
  複数端末の同日回答数を厳密に合算する方式ではない。確認画面にその旨を書く。
- 復元の取り消しの対象にも、これらのキーを含める。
- **Google Drive 同期の対象には含めない**。既存の統合ロジックに触れないため。
  Drive 同期はバックアップと同じ `buildBackup` / `parseBackup` を使うので、Drive 用の書き出しは従来どおり
  版 5・日別記録と表示設定なしで作る（`buildBackup({ forDrive: true })`）。まだ更新していない端末が Drive のファイルを読めなくならないようにするため。
  版 6 になるのは、ファイルへの書き出しとコピーだけ。

## 段階 4：「復習」画面

- ナビを「ホーム / 演習 / 復習 / 設定」の 4 つにする。
- 内容：今日の復習件数、苦手の一覧（現行の苦手リストのシートと同じ情報）、苦手ドリルへの入口、
  復習の成果（「苦手を N 問克服できました」）。
- 現行の「苦手を解く」「一覧を見る」はホームに残し、復習画面へ移るだけにはしない。
- 復習の成果：回答の前後で苦手の状態を比べ、「苦手だった問題に正解した数」と「苦手から外れた（克服した）数」を数える。
  演習 1 回分はメモリ上のカウンタで、出題し直すたびにリセットする。その日に克服した数は日別記録の `gr` に保存する。
  既存の間隔復習のルールは変更しない。再読み込み後の演習や過去の演習の成果は推測せず、表示しない。
- ホームのメッセージ「要復習が N 問あります」はタップで復習画面へ移れるようにする。

## コードの置き方

- 純粋なロジック（日別記録、目標、カレンダーの月モデル、進捗の計算）は `next/` の `activity.mjs`・`preferences.mjs`・`progress.mjs`
  を参考に `src/` へ置く。DOM に触れない形にして、node でテストできるようにする。
- 現行の `index.html` はグローバル関数と classic script で書かれているため、接続用の薄いファイル（`home.js` の隣）で呼び出す。
  新ファイルは `sw.js` の `ASSETS` に追加し、オフラインでも読み込めるようにする。
- 既存の巨大な `index.html` には、接続に必要な最小限の変更だけを入れる。

## 記録の安全

- 既存の保存キー（苦手・学習済み・成績・設定・セッション）の形式と意味は変更しない。`toeic_next_v1` は使わない。
- 着手前に復元用の git タグ（例：`stable-before-port-20261029`）を打つ。
- 新しいキーが壊れていたり読めなかったりしても、アプリは起動し、既存の学習を続けられる（`loadJSON` と同じ扱い）。
- 保存に失敗しても学習は続けられる。目標・日別記録の保存失敗でバックアップや Drive 同期を巻き込まない。

## 追加：設定ページの「学習の目標」（2026-10-29）

設定ページに、今日の目標問題数と即答の目標タイムを編集するセクションを足した。

- 今日の目標：0〜200 の整数を自由に入力（0 は目標なし）。5・10・20・30 と「目標なし」のワンタップボタン。
  ホームのダイアログの選択肢には、既定の選択肢に今の値を足して出す。日別記録の目標 `g` も同じ範囲の整数を許す。
- 即答の目標タイム：単語は初期値 5 秒（1〜30 秒、0.5 秒刻み）、文法は初期値 20 秒（5〜120 秒、1 秒刻み）。
  「即答」の判定とバッジの段階をこのタイムから決める（単語は 0.7 倍以内が「瞬殺」・1.2 倍以内が「ナイスペース」、
  文法は 0.5 倍以内が「爆速」・1 倍以内が「本番ペース」）。初期値では従来の境界と同じ。変更は以後の回答にだけ効く。
- 保存は `toeic_prefs_v1` の `{ dailyGoal, paceTarget: { vocab, grammar } }`。壊れた値は初期値に戻る。
- バックアップの `prefs` には `paceTarget` も含める。ファイルに無い項目・壊れた項目は「今のまま」にする（Drive 同期の対象外は変わらない）。

## 追加：解いている間のカウントアップ（2026-10-29）

演習画面の下（フッター）に、問題が出た瞬間からの経過時間を 0.1 秒刻みで表示する（「⏱ 3.2」）。
出題のカードの上には出さない（目に入りすぎて気になる人がいるため）。

- 場所は、フッターにある平均ペースの枠（`#pace-text`）。解いている間はカウントアップ、回答すると平均ペース（「⏱ 4.1s/問」）に戻る。
  回答後は、カードに今までどおり結果バッジ（「⚡ 瞬殺！ 3.2秒」など）が出る。枠を共用するので、フッターの項目が増えず、位置も一定。
- 数える時計は記録される解答時間と同じ（`questionShownAt`）。
- 単語の 4 モードと文法で出る。前の問題の見直し中、演習画面以外では出さない（平均ペースの表示のまま）。60 秒以上は「60+」で止める。
- 即答の目標タイムを超えたら、点線の枠と薄さで知らせる（強い色は使わない）。
- 設定ページの「学習の目標」に表示のオン／オフ（初期値オン）。`toeic_prefs_v1.liveTimer`（真偽値）。バックアップの `prefs` に含め、真偽値でない値は取り込まない。
- 純粋ロジックは `src/pace.js`（`formatElapsed` / `isOverTarget` / `normalizeLiveTimer`）、ブラウザの確認は `tests/live-timer.test.js`。
