# iOS テーマの横画面版（Mac / iPad 風）— 設計

作成日: 2026-11-04 / 状態: 設計の合意済み・実装前

## 目的

iPad の横向きや、Mac の広いウィンドウで使うとき、iPhone 用の細い縦一列の画面が中央に残るだけになっている。
iOS テーマの中に、Mac / iPad のアプリらしい配置（左サイドバー、右の絞り込みパネル）を作る。
他のテーマには、あとから広げる（今回は対象外）。

## 合意した方針

| 項目 | 決めたこと |
|---|---|
| 適用範囲 | iOS テーマで、画面の幅が 1000px 以上のときだけ。それ以外は今のまま。 |
| 第一段階の中身 | 左サイドバー ＋ 各画面を中央寄せ ＋ 右側の絞り込みパネル |
| 演習画面の中身 | 今の縦並び（問題カード → 選択肢）のまま。左右二列にするのは第二段階。 |
| 絞り込みパネル | 演習画面のときだけ、右側に固定（幅 320〜380px、画面の高さいっぱい）。最初は開いておき、開閉を端末に覚えさせる。 |
| 他のテーマ | 対象外。影響がないことを検証で確かめる。 |

## 設計

### 1. ファイルと読み込み
- 新規: `css/theme-ios-wide.css`。中身はすべて `@media (min-width: 1000px)` と `[data-theme="ios"]` で囲む。
- 新規: `js/ios-wide.js`（パネルの開閉の記憶だけ。60 行程度を見込む）。
- 登録先: `index.html`（link / script と読み込み順のコメント）、`sw.js` の ASSETS、`upload.py` の FILES。
  `tests/test_file_lists.py` が、sw.js と upload.py の一致を確かめる。

### 2. 左サイドバー
- 既存の `.top-page-nav`（下に浮いたタブバー）を、CSS だけで左の縦のガラスのサイドバー（幅 240px）に変える。
- `.top-page-nav` は、ブランド（マスコットと「TOEIC Practice」）と、4つのタブ（`.top-page-tabs`）でできている。サイドバーでは、ブランドを上に、タブを縦に並べる。
- アイコンと文字を横に並べ、選択中の項目を丸く強調する。ガラスの質感は既存の変数（`--ios-glass` など）を使う。
- 横画面では、タブバーを格納する動き（`.ios-nav-stowed`）と、下のつまみ（`.ios-grabber-bottom` / `.ios-grabber-footer`）は無効にする。
  サイドバーは常に表示。`#app` の下の余白（`--ios-tab-space`）も 0 にする。
- 演習画面の見出し行の格納（上へのスワイプ）は、そのまま使える。

### 3. 各画面の幅
- `#app` の最大幅（520px）を外し、左サイドバーと本文の二列にする。
- 本文は、読みやすい幅で中央に置く。演習 640px、復習 720px、設定 640px。
- ホームは、`home.css` にある 1024px 以上の二列配置（最大 1080px）をそのまま使う。
  `home.css` の `#app.page-home { max-width: 1080px }` は、サイドバーを含めた幅として効くので、iOS 横画面では上書きして、本文の幅として扱う。

### 4. 右側の絞り込みパネル
- 今の `#filter-drawer`（`.top-sheet`、上から降りるシート）を、演習画面のときだけ、右側の固定パネルにする。幅は `clamp(320px, 30vw, 380px)`（1000px では 320px、1280px では 380px）で、サイドバーと同じく画面の高さいっぱいに広げる。日付・品詞のチップは折り返し、「この条件で解く」はパネルの下に残す（sticky）。
  上から降りる動き（`translateY(-100%)`）をやめ、本文の右の列に置く。
- パネルを出すかどうかは、`#app` の `ios-filter-panel-open` クラス（`js/ios-wide.js` が付け外し）か、既存の `.top-sheet.open`（ホームの「範囲を指定」などが開いたとき）のどちらか。
  ページ切り替えで呼ばれる `closeFilterSheet()` は `.open` だけを外すので、パネルは開閉の記憶のとおりに残る。
- 暗幕（`#sheet-overlay`）は、絞り込みだけが開いているときは出さない。下のシート（苦手リストなど）が開いているときは、今までどおり出す。
  CSS の `:has()` で切り分ける。
- 最初から開く。`js/ios-wide.js` が、起動時に横画面ならパネルを開く。
  ユーザーが「絞り込み」ボタンか ✕ で開閉したときだけ、その状態を `localStorage`（キー `toeic_ios_filter_panel`）に覚える。
  下のシート（苦手リストなど）を開いても、パネルは閉じない（暗幕と下のシートがパネルの上に重なる）。
- 条件を変えるとすぐ問題に反映される今の作りは、変えない。
  「この条件で解く」ボタンは、横画面では件数の表示を残し、押すとパネルを閉じる。

### 5. 変えないもの
- 幅 1000px 未満の表示、他の 7 テーマ、データ、問題の出題の仕組み。

## 確認する方法
1. `ios-isolation.cjs`（検証用スクリプト。リポジトリ外）に、横画面（幅 1280px）の項目を足す。
   - サイドバーが出て、タブバーとつまみが出ない。
   - パネルが開いた状態で始まり、ボタンで閉じて、再読み込みしても閉じたまま。
   - 幅を 1000px 未満に戻すと、今までの表示に戻る（再読み込みなしでも）。
   - 他のテーマは、`theme-ios-wide.css` あり・なしで、計算済みのスタイルが同じ。
2. 既存の Python のテストと、関係する Node のテスト（practice-chrome、sheets など）。
3. ブラウザで、幅 1280px と 1024px で、ホーム・演習・復習・設定を目で確かめる。
4. iPad / Mac の実機での見え方は、公開後に本人が確認する（パソコンの表示では再現できない部分がある）。

## 注意点・リスク
- `:has()` を使う。対応していない古いブラウザでは、暗幕が出るだけで、使えなくなることはない（横画面を使う iPad は新しい OS が前提）。
- ホーム画面の既存の二列配置と、新しいサイドバーの幅の計算が重なるので、1024px ちょうど付近で、見た目が崩れないかを重点的に確かめる。
- `#filter-drawer`、`.top-page-nav`、各ページは、`index.html` で `#app` の直下に並んでいる（確認済み）。この並びを前提にして、グリッドで配置する。
