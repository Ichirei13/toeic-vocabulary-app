# 学習機能の追加（発音・連続日数・統計・優先出題・穴埋め）設計

## 背景と目的

他のTOEIC学習アプリ（abceed、Santa、mikan、スタディサプリ TOEIC など）の機能を参考に、
このアプリに足りない機能を取り入れる。目的は、毎日続けやすくすることと、復習の効率を上げること。

現状のアプリは `index.html` 1ファイル（外部ライブラリなし、ビルドなし）と `data/words.js`・`data/grammar.js` でできている。
単語は英→日、日→英、カード、タイプの4モードがあり、苦手語の間隔復習（`REVIEW_INTERVALS = [1, 3, 7]`）、
バックアップと復元、オフライン対応を持つ。

## 追加する機能

1. 発音ボタン
2. 学習ログ（連続日数と統計の土台）
3. 連続日数と今日の目標
4. 学習統計
5. 期限の来た語を優先出題
6. 穴埋めモード（5つ目のモード）

新しいライブラリは使わない。1ファイル構成を保つ。

## 1. 発音ボタン

- 単語と例文に 🔊 ボタンを付け、`speechSynthesis`（`lang = 'en-US'`）で読み上げる。
- `speechSynthesis` が使えない端末では、ボタンを出さない。
- カードモードでは、ボタンのクリックでカードがめくれないよう `stopPropagation` する。
- 読み上げ中に別の読み上げを始めるときは `cancel()` してから始める。
- 保存するデータはない。自動再生はしない。
- 例文に日本語訳が `（…）` で付いている語（teppan）は、読み上げる前に `（…）` の部分を取り除く。

## 2. 学習ログ

- 新しい保存キー `toeic_daily_log`。形は次のとおり。

  ```
  { "2026-10-21": { "v": [回答数, 正解数], "g": [回答数, 正解数] }, ... }
  ```

  `v` は単語、`g` は文法。日付は端末のローカル日付（`YYYY-MM-DD`）。
- 古いものから削除し、最大400日分を持つ。
- 記録は `recordActivity(app, isCorrect)` の1か所にまとめる。
  単語は `recordWeak` を呼んでいる箇所、文法は `recordWeakGrammar` を呼んでいる箇所から呼ぶ。
  「わからない」は不正解として数える。
- バックアップの `RECORD_KEYS` に `dailyLog` を追加する。復元時の検証は既存の `sanitize*` と同じ作りにする。
  形の正しくない日付や数値は捨てて、捨てた件数を返す。
- 過去の履歴はないので、連続日数は導入した日から数え始める。

## 3. 連続日数と今日の目標

- 画面上部に「🔥3日連続 ・ 今日 12/20」の形で出す。
- 今日の数は、単語と文法の回答数の合計。
- 連続日数は学習ログから計算する。今日に1回以上回答があれば今日から、なければ昨日から、さかのぼって連続している日数を数える。
- 目標は 10 / 20 / 50 / 100 から選べる。初期値は20。設定として `toeic_settings` に保存する（`goal`）。
- 目標を達成したら、表示の見た目を変える（通知や音は出さない）。

## 4. 学習統計

- フッターに「統計」リンクを足し、既存のボトムシートで開く。
- 表示する内容:
  - 今日・直近7日・累計の回答数と正答率
  - 直近14日の回答数の棒グラフ（CSS のみ）
  - 学習済み語数（全モードのどれかで学習済みの語数）と、全体に対する割合
  - 苦手の数と、要復習の数
- 棒グラフは外部ライブラリを使わず、`div` の高さで描く。

## 5. 期限の来た語を優先出題

- 絞り込みに「出題順: ランダム / 要復習を先に」を足す。**初期値は「要復習を先に」**。
- 要復習の語（シャッフル済み）を先頭に、残りをシャッフルして続ける。単語と文法の両方に効かせる。
- 苦手で絞り込んでいるとき（`weakFilter` が `all` 以外）は出題範囲がもともと苦手の語なので、この設定は効かせない。
- この設定は `sessionSignature` に含める。保存した出題順を再利用する条件に入れることで、設定を変えたときに出題順が作り直される。
- 設定として `toeic_settings` に保存する（`priority`）。

## 6. 穴埋めモード

- 単語モードに5つ目の `cloze`（穴埋め）を追加する。`VOCAB_MODES`、`MODE_LABELS`、`restoreSettings` の許可リスト、モードの切り替えUIに足す。
- 出題:
  - 例文の見出し語を `-------` に置き換えて見せる。例文の `（…）` の日本語訳は伏せる。
  - 選択肢は `buildOptions` をそのまま使い、英単語の4択にする。
  - 回答後は例文を元に戻し、活用していた部分をハイライトする。
- 空欄にできるかの判定（`findBlank(word)`）:
  1. 見出し語がそのまま例文にある（大文字小文字は区別しない、単語境界で一致）なら、それを空欄にする。
  2. なければ語幹で一致させる。語尾の `ion/ing/ed/es/s/e/y` を取った形（5文字以上の語のみ）に続けて単語の文字が続く部分を空欄にする。
  3. どちらでも見つからない語は、穴埋めの出題から外す。
- 実データでの見込み（全2,056語）: 完全一致が1,796語、語幹一致が225語、空欄にできない語が35語。
  約98%が出題できる。出題できない語は `opted for` のように活用した句動詞が中心。
- 苦手と学習済みの記録は、これまでと同じくモード別に持つ（`weakByMode.cloze`、`seenByMode.cloze`）。
- 既存のバックアップに `cloze` がなくても、復元できること（空として扱う）。
- 穴埋めモードのときは、出題の絞り込み（`applyFilters`）で空欄にできない語を除く。

## 変更するファイル

- `index.html`: 上記すべて。新しい関数はそれぞれ小さく分け、既存の関数への変更は呼び出しの追加にとどめる。
- `sw.js`: ファイルを足さないので変更なし。ただしキャッシュを更新するため、`CACHE` のバージョンを上げる。
- `data/`: 変更なし。

## エラー処理と互換性

- `localStorage` が使えない場合は、既存の `loadJSON` / `saveJSON` と同じく黙って続ける。
- 既存の記録（苦手、学習済み、設定、出題順）は壊さない。新しいキーは足すだけ。
- 古いバックアップ（`dailyLog` なし）は復元できること。復元しても学習ログは消さず、バックアップに `dailyLog` がある場合だけ置き換える。

## テスト

テスト環境がないため、次の方法で確認する。

- ロジックを `index.html` から取り出して Node で確認する:
  - 連続日数の計算（今日あり、今日なし昨日あり、途切れ、空）
  - `findBlank`（完全一致、語幹一致、一致なし、`（…）` の除去）
  - 優先出題の並べ替え（要復習が先頭に来ること、ほかの順は崩れないこと）
  - 学習ログの検証とバックアップの復元（壊れた値、古い形式）
- 画面は Playwright（Chromium）で動かして確認する:
  - 各モードで回答し、ログと表示が更新されること
  - 🔊 の表示と、カードモードでめくれないこと
  - 統計シートの表示
  - 穴埋めモードの出題と回答後の表示
  - バックアップを書き出して復元しても記録が残ること
