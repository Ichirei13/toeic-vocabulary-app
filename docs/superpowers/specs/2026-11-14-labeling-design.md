# ラベリング機能 — 設計

## 目的・背景
間違えた問題は、いまも自動で苦手リストに入る。ただ苦手リストは「間違えた問題」しか入らず、決めた回数だけ正解すると自動で消える。
実際には「正解したけど自信がなかった問題」や「暗記しておきたい問題・単語」もあり、それらを**自分で選んで、自分で外すまで残しておける**場所が欲しい。

そこで、**自分で名前を付けたラベルをいくつか作り、問題や単語にワンタップで付けられる「ラベリング機能」**を作る。苦手リストとは完全に別の仕組みにする。

## ゴール
- 解答したあとに 🏷 ボタンを1回タップすると、「最後に使ったラベル」が付く（YouTube の「保存」と同じ考え方）。
- もう一度タップするか長押しすると、ラベルを選ぶ画面が開き、付けるラベルを選び直したり、新しいラベルを作ったりできる。
- ラベルは自分で作れて、名前の変更と削除もできる。
- ラベルごとに、**一覧で見返す**ことも、**そのラベルの問題だけで解き直す**こともできる。
- Google ドライブ同期とバックアップで、端末どうしのラベルがそろう。

## 作らないもの（非ゴール）
- 苦手リストとの連動。ラベルを付けても外しても、苦手の記録（復習日・連続正解・克服）は変わらない。逆に、苦手の記録が変わってもラベルは変わらない。
- 正解したら自動でラベルが外れる、などの自動処理。付け外しはすべて手動。
- ラベルの並べ替え、色分け、アイコン。
- `next/`（試用版 Study Desk）への対応。従来版（`index.html`）だけを対象にする。
- Obsidian 連携、単語帳 PDF への対応。

## 失敗とみなすこと（アンチゴール）
- ラベルの操作が、苦手リストの記録を変えてしまう。
- ドライブ同期のあと、外したはずのラベルや消したはずのラベルが、別の端末の古い記録から復活する。
- 解いているときにうっかりタップして、ラベルが外れる。
- 2台で使い始めると、最初から用意しているラベル「あとで見る」が2つになる。

## 決めたこと（ユーザーと合意済み）
- 名前は「ラベリング機能」（「お気に入り」「暗記リスト」ではない）。
- ラベルは自分で複数作れて、名前を付けられる。
- 解答後の画面には 🏷 ボタンを1つだけ置く（ラベルを並べる案は不採用）。
- タップすると「**最後に使ったラベル**」に追加する。もう一度タップするか長押しで、ラベルを選ぶ画面を開く。
- 端末どうしの同期は、苦手リストと同じ扱いにする（バックアップとドライブ同期の両方。下の「やり方の比較」の案1）。

## やり方の比較（Approaches）
| 案 | 中身 | 良い点 | 弱い点 |
|---|---|---|---|
| **1. 苦手リストと同じ扱い（採用）** | 学習記録（`RECORD_KEYS`）に足し、バックアップとドライブ同期の両方で統合する。外したことも時刻つきで記録し、復活しないようにする | スマホで付けたラベルが、同期で PC にも出る | 作業が多い。アプリを更新していない端末で同期すると、ラベルを含まない状態でクラウドに書き戻すことがある |
| 2. バックアップファイルだけ | ポモドーロや日別記録と同じ `EXTRA_KEYS` に入れる | 作業が少ない | ドライブ同期ではラベルが移らない |
| 3. 苦手の記録に相乗り | 苦手の各項目に「ラベル」欄を足す | 一番楽 | 苦手から外したときにラベルも消えやすい。「苦手とは分けたい」という希望に合わない。検討の早い段階で外した |

ユーザーは案1を選んだ。スマホで解きながらラベルを付けて、PC で見返す使い方を想定しているため。

## 画面と操作

### 1. 解答後の 🏷 ボタン
- **出す場所**: 文法ドリルと単語ドリルの両方で、回答したあと（正誤と解説が出たあと）に出す。単語の「カード」モードは、裏返したあとに出す。「← 前へ」で前の問題を見直しているときも出す（見直している問題に付く）。回答する前は出さない。
- **見た目**: ラベルが1つも付いていなければ白抜き、1つ以上付いていれば塗りつぶしにする。付いているラベルが1つなら、ボタンの横にそのラベル名を小さく出す（2つ以上なら「2件」）。
- **タップ（ラベルなし）**: 「最後に使ったラベル」を付ける。トーストで「『自信なし』に追加しました」と出し、トーストに［変更］ボタンを付ける。［変更］を押すとラベルを選ぶ画面が開く。トーストは既存の `showToast` のように数秒で消える。ボタン付きのトーストは新しく作る。
- **タップ（ラベルあり）**: ラベルを選ぶ画面を開く。**タップでラベルは外さない**（うっかり外さないため）。
- **長押し**: ラベルの有無にかかわらず、ラベルを選ぶ画面を開く。長押しの判定時間は builder が決める（目安は 500ms）。長押しで選ぶ画面が開いたときは、そのあとのタップ扱いを打ち消す。
- **キーボード**: `L` キーでタップと同じ動きをする（PC 用）。いまは使っていないキー。ラベルを選ぶ画面やシートが開いているときは何もしない。

### 2. ラベルを選ぶ画面
```
ラベルを選ぶ
☑ 自信なし
☐ 暗記
☐ 本番前
＋ 新しいラベル
```
- 全ラベルをチェックボックスで並べる。チェックすると付き、外すと外れる。結果はすぐに保存する（「保存」ボタンは置かない）。
- **チェックを付けたラベルが「最後に使ったラベル」になる**。チェックを外しただけでは変わらない。
- 「＋ 新しいラベル」で名前を入れて作り、作ったラベルはその場でチェックが付いた状態にする（＝最後に使ったラベルになる）。
- 出し方は既存の下から出るシート（`openSheet`）を使うか、小さなポップアップにするかを builder が決める。ただし、**解いている画面の状態（回答済み・解説の表示）を壊さずに閉じて戻れること**。

### 3. ラベルの置き場所（使う場所と編集する場所を分ける）
| やること | 場所 |
|---|---|
| ラベルの中身を見返す・「このラベルで解く」 | フッターの「ラベル」（下から出るシート） |
| ラベルを作る・名前を変える・削除する | 設定画面の「ラベル」セクション |
| 解いている途中で新しいラベルを作る | 🏷 の選択画面の「＋ 新しいラベル」 |

名前の変更と削除は、設定画面の1か所でだけできるようにする（同じ操作を2か所に置かない）。

#### 3a. ラベル一覧（フッター）
- 入口: 画面下のフッターの「苦手リスト」の隣に「ラベル」を置く。押すと下から出るシート（`openSheet`）で開く。
- ラベルごとに名前と件数（文法 n 問・単語 n 語）を並べる。名前の変更・削除のボタンは置かない。
- 一番下に「ラベルを編集 →」を置き、設定画面の「ラベル」セクションへ移る（シートを閉じ、設定ページを開いてそのセクションまでスクロールする）。
- ラベルを1つ押すと、そのラベルの中身（下の 4）を開く。中身から一覧へ戻れるようにする。

#### 3b. ラベルの編集（設定画面）
- 設定画面（`home.js` の設定ページ）に「ラベル」セクションを足す。置き場所は「苦手・復習の設定」のすぐ下。
- ラベルごとに名前と件数を並べ、「名前を変える」「削除」ができる。
- 削除は、付いている件数を出して確認してから行う（「『暗記』を削除します。付いている 12 件からこのラベルが外れます」）。問題や単語そのもの、苦手の記録は消えない。
- 「＋ 新しいラベル」。
- 名前のきまり（下の「名前のきまり」）に合わない名前は、理由を出して断る。

### 4. ラベルの中身（一覧で見返す・解き直す）
- 文法と単語をタブ（またはチップ）で切り替える。最初は、いま開いているドリル（`state.app`）の方を見せる。
- **文法**の1件: 本のバッジ、問題文、正解の選択肢、解説（折りたたみ。既存の苦手リストの表示に合わせる）、「ラベルを外す」。
- **単語**の1件: 単語、意味、例文、「ラベルを外す」。
- 並び順は「付けた順（新しい順）」と「本・章順／ABC順」。苦手リストの並べ替えの見た目に合わせる。
- 上に「**このラベルで解く**」ボタンを置く。文法タブなら文法ドリル、単語タブなら単語ドリル（モードはいまのモード）で、そのラベルが付いた問題だけを出す。0件のときは押せないようにする。

### 5. 演習の絞り込み
- 「このラベルで解く」は、**絞り込みの条件の1つ**として作る（金の文法の「ルールで解く」= `state.grammarRule` と同じ考え方）。
  - 文法: `state.grammarLabel`（ラベル ID か `null`）、単語: `state.vocabLabel`。
  - ラベルの条件が付いているときは、ほかの絞り込み（本・章・苦手）と**組み合わせず、ラベルの問題だけを出す**。
  - 絞り込みシートに「ラベル: 〇〇 ✕」の表示を出し、✕で解除できるようにする。ラベルを選ぶ UI を絞り込みシートに置くかどうかは builder が決める（ラベル一覧からの起動だけでもよい）。
  - 絞り込み中のラベルが削除されたら、条件を解除する。
- `grammarLabel` / `vocabLabel` は `grammarRule` と同じく保存される設定（`settingsSnapshot` のキー）に入れ、次に開いたときも続ける。`restoreSettings` で「文字列で、削除されていないラベルの ID」か確かめ、違えば `null` に戻す。
- 解いている途中で、いま出ている問題からそのラベルを外しても、出題中の問題の並びはそのまま（次に絞り込みを適用したときに反映）。
- 問題データに無くなった問題 ID や見出し語に付いたラベルは、一覧にも件数にも出さない（データは消さない）。苦手リストの扱いと同じ。

## データ

### 保存キーと形
保存キー `toeic_labels_v1`（`LABELS_KEY`）。値:
```js
{
  labels: {
    // ラベル ID → ラベル
    "default": { name: "あとで見る", created: 1731500000000, u: 1731500000000 },
    "l_k3f9a2": { name: "自信なし", created: 1731500100000, u: 1731500100000 },
    "l_x81bq0": { name: "暗記", created: 1731500200000, u: 1731500300000, deleted: true }
  },
  items: {
    // "ラベルID|項目キー" → 付いているか
    "l_k3f9a2|g:1023": { on: true,  u: 1731500400000 },
    "l_k3f9a2|w:allocate": { on: false, u: 1731500500000 }  // 外した記録（統合で復活させないため）
  }
}
```
- **項目キー**: 文法は `g:<問題ID>`（例 `g:1023`）、単語は `w:<見出し語>`（例 `w:allocate`）。単語は**モードに関係なく1つ**にする（苦手リストの `w:<mode>:<word>` とは違う）。
- **ラベル ID**: 作るときにランダムに作る（`l_` + 短いランダム文字列。2台で同時に作っても重ならない長さにする）。最初から用意するラベルだけは **固定 ID `default`** にして、2台で使い始めても1つにまとまるようにする。
- **u**: 最後に変えた時刻（ミリ秒）。名前の変更、削除、付け外しのたびに更新する。
- ラベルの削除は `deleted: true` にして残す（消した記録）。画面には出さない。
- 外したときは `items` から消さず、`on: false` にして残す（外した記録）。
- 消した記録や外した記録をいつまで残すか（掃除するか）は builder が決める。ただし掃除するなら、統合で復活しないことをテストで確かめる。

### 最後に使ったラベル
- 端末ごとの設定として持つ（`SETTINGS_KEY` の `lastLabelId`）。同期では、この端末の値を使う（設定はいまも端末側を優先している）。
- 指しているラベルが削除されていたり、存在しなかったりしたら、残っているラベルのうち最後に作ったもの、それも無ければ `default` を使う。
- ラベルが1つも無い（`default` も削除した）ときに 🏷 をタップしたら、追加はせず、ラベルを選ぶ画面を開く（そこで新しく作れる）。

### 最初の起動
- `toeic_labels_v1` が無ければ、`default`（名前「あとで見る」）だけを作る。このとき `u` は 0 にして、ほかの端末で名前を変えたり削除したりした記録が必ず勝つようにする。

### 名前のきまり
- 前後の空白を除いて 1〜20 文字。空の名前は作れない。
- 同じ名前のラベル（削除したものを除く）は作れない。名前の変更で同じ名前になる場合も断る。
- 表示するときは必ず `escapeHtml` を通す。
- 同期の結果として同じ名前のラベルが2つになった場合（2台でそれぞれ「暗記」を作った、など）は、そのまま2つ出す。自動ではまとめない。

## 統合（ドライブ同期とバックアップの「統合」復元）
純粋な関数として `src/labels.js` に置き（`src/review.js` と同じ形。DOM にも保存にも触れない）、`tests/unit/labels.test.js` で単体テストする。
- `labels`: ID ごとに、`u` が新しい方を採る。同じ `u` なら `deleted: true` の方を採る。
- `items`: キーごとに、`u` が新しい方を採る。同じ `u` なら `on: false` の方を採る。
- 削除されたラベルの `items` は、統合のあとで画面に出さない（データ上は残っていてよい）。
- 上書き復元のときは、ファイルの値で置き換える（ほかの記録と同じ）。

### テストで確かめること（最低限）
- スマホで外したラベルが、PC の古い記録から復活しない。
- PC で付けたラベルと、スマホで付けた別のラベルが両方残る。
- 片方で名前を変え、もう片方で何もしていなければ、新しい名前になる。
- 片方で削除したラベルが、もう片方の古い記録から復活しない。
- 2台とも最初の `default` のままなら、`default` は1つだけ。
- 壊れた値（形の違う `labels`／`items`、文字列でない名前、21文字以上の名前など）は読み込み時に取り除き、ほかの正しい値は残す。

## 既存の仕組みへのつなぎ込み
- **保存**: `saveJSON(LABELS_KEY, …)` / `loadJSON`。保存に失敗したときは、既存の保存失敗の通知（`reportSaveFailure`）に乗る。
- **学習記録として登録**: `RECORD_KEYS` に `labels: LABELS_KEY` を足す。これでバックアップの取り消し（`LOCAL_BACKUP_KEYS`）と、別タブへの反映（`CROSS_TAB_KEYS`）にも入る。別タブで変わったら、このタブのメモリ（`state.labels`）を読み込み直す（`reloadRecordsFromStorage` の中で）。
- **バックアップファイル**: `buildBackup` に `labels` を足す。ファイル形式を**版7**に上げ、`BACKUP_MIGRATIONS[6]` で「`labels` が無ければ空（＝その端末の今のまま）」にする。読み込み時の形の確認（`sanitize…`）を足す。
- **ドライブ同期**: `buildBackup({ forDrive: true })` にも `labels` を入れ、`getCurrentLocalRecords` と `mergeBackupRecords` に `labels` の統合を足す。ドライブ用の版（`BACKUP_FORMAT_DRIVE = 5`）は**上げない**（更新していない端末が読めるように）。版5のファイルに `labels` が無いときは「この端末の今のまま」にする。
  - 既知の弱点（ユーザーに説明済み）: アプリを更新していない端末で同期すると、その端末はラベルを知らないため、ラベルの無いファイルをクラウドに書き戻すことがある。その後、更新済みの端末で同期すれば、その端末のラベルは残る（「無い」は「今のまま」として扱うため）。
- **Service Worker とアップロード**: `src/labels.js` と新しい `js/labels*.js` を `sw.js` の `ASSETS` と `upload.py` の `FILES` に足し、`sw.js` の版を上げる。`index.html` の読み込み順は README の注意に従う。

## 設計者（Claude）が決めたこと（ユーザー承認済み）
- 1つの問題に複数のラベルを付けられる（フォルダではなく付せんの扱い）。
- ラベルは文法と単語で共通。単語はモードに関係なくラベルが付く。
- ラベルが付いている状態でタップすると、外さずに選ぶ画面を開く。
- 最初から「あとで見る」（固定 ID `default`）を1つ用意する。
- PC 用のショートカットは `L`。
- 中身を見る入口はフッターの「苦手リスト」の隣、編集は設定画面（ユーザーと合意）。ホーム画面や PC のサイドバーには、今回は置かない。
- 「このラベルで解く」は、ほかの絞り込み（本・章・苦手）と組み合わせない。
- ラベル名は 1〜20 文字で、同じ名前は不可。

## builder に任せること
- ファイルの分け方（例: `src/labels.js` に純粋なロジック、`js/labels.js` に保存と画面）。
- 🏷 ボタン、トースト、ラベルを選ぶ画面の見た目。既存のテーマ（iOS 風など）に合わせる。
- 長押しの判定時間、トーストの表示時間。
- ラベルの中身の画面の細かいレイアウト。
- ブラウザを動かすテスト（Playwright）の範囲。少なくとも「タップで最後のラベルに付く」「付いている状態でタップすると選ぶ画面が開き、外れない」「このラベルで解くでそのラベルの問題だけが出る」を確かめる。
