# ラベリング機能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 自分で名前を付けたラベルを、解答後の 🏷 ボタン1タップで問題・単語に付けられるようにし、ラベルごとに見返す・解き直す・端末間で同期できるようにする。

**Architecture:** ラベルの記録（ラベル定義と「どの項目にどのラベルが付いているか」）は、時刻つきの1つのオブジェクトとして `toeic_labels_v1` に保存する。統合・検証・付け外しは DOM を触らない純粋関数（`src/labels.js`、`StudyCore` に生やす）にまとめ、Node で単体テストする。保存・state・同期のつなぎ込みは `js/labels.js`、画面（🏷 ボタン・選ぶ画面・一覧・設定セクション・絞り込み）は `js/labels-ui.js` に置く。

**Tech Stack:** 素の JavaScript（グローバル共有の `<script>`）、localStorage、Node 標準テストランナー（`node --test`）、Playwright（Chromium。`NODE_PATH=$(npm root -g) node tests/xxx.test.js`）、pytest（配線チェック）。

**Spec:** `docs/superpowers/specs/2026-11-14-labeling-design.md`（実装者は必ず両方読む）

## Global Constraints

- 保存キーは `toeic_labels_v1`。最初から用意するラベルは ID `default`・名前「あとで見る」・`created: 0`・`u: 0`。
- 項目キーは文法 `g:<問題ID>`、単語 `w:<見出し語>`（モードに関係なく1つ）。
- ラベル名は前後の空白を除いて 1〜20 文字。削除していないラベルと同じ名前は不可。表示は必ず `escapeHtml` を通す。
- 統合: ラベルも項目も `u` が新しい方。同じ `u` なら `deleted: true` / `on: false` の方。
- ラベルの操作は苦手の記録（`grammarWeakData` / `weakByMode` / `weakDeleted`）を一切変えない。
- バックアップファイルの版は 7（`BACKUP_FORMAT = 7`）。ドライブ用の版 `BACKUP_FORMAT_DRIVE = 5` は上げない。ファイルに `labels` が無ければ「この端末の今のまま」。
- 新しいファイルは `index.html`（読み込み順コメントも）・`sw.js` の `ASSETS`・`upload.py` の `FILES` に足し、`sw.js` の `CACHE` を `toeic-drill-v16` に上げる。
- `next/`（試用版）は触らない。
- 既存のコメント・文言の書き方（です・ます無しの短い日本語コメント）に合わせる。

## Review Focus

1. **2台で別々に作った同名ラベル**（どちらも「暗記」）→ 同期後に2つとも残り、片方の項目がもう片方に混ざらない。→ Task 1 のテスト `merge_keeps_two_labels_with_the_same_name`。
2. **絞り込み中のラベルを設定画面で削除** → 次に出題するときラベル条件が外れ、0問の画面で固まらない。→ Task 4 のテスト `deleting_the_filtered_label_clears_the_filter`。
3. **既存ユーザーの「出題の続き」**（保存済み `toeic_session`）→ 更新後もラベル未使用なら続きがそのまま使える（`sessionSignature` が変わらない）。→ Task 4 のテスト `session_signature_unchanged_without_label_filter`。
4. **ラベルを選ぶ画面を開いて閉じたあと** → 解いていた問題の回答済み状態・解説・「次へ」がそのまま残る。→ Task 3 のテスト `picker_close_keeps_answered_state`。
5. **版 6 以前のバックアップを上書き復元** → ラベルは消えずに今のまま。→ Task 2 のテスト `restore_old_backup_keeps_labels`。

**Interfaces:**
- Produces（すべて純粋。引数のストアを変更せず、新しいストアを返す）:
  - 定数 `DEFAULT_LABEL_ID = 'default'`, `DEFAULT_LABEL_NAME = 'あとで見る'`, `LABEL_NAME_MAX = 20`
  - `emptyLabelStore() -> { labels: { default: { name: 'あとで見る', created: 0, u: 0 } }, items: {} }`
  - `isLabelItemKey(key: string) -> boolean` — `/^g:[1-9]\d{0,8}$/` か `/^w:.+$/`
  - `sanitizeLabelStore(raw) -> { data: Store, invalid: number }` — `raw` が plain object でなければ `{ data: { labels: {}, items: {} }, invalid: raw == null ? 0 : 1 }`。ラベルは「ID が `/^(default|l_[a-z0-9]{6,16})$/`、`name` が規則に合う文字列、`created`/`u` が 0 以上の有限数、`deleted` は省略か `true`」だけ残す。項目は「キーが `<ラベルID>|<項目キー>` で両方が正しい形、`on` が真偽値、`u` が 0 以上の有限数」だけ残す。捨てた数を `invalid` に数える。`default` を補ったりはしない。
  - `mergeLabelStores(a: Store, b: Store) -> Store`
  - `validateLabelName(store, name: string, exceptId?: string) -> { ok: true, name: string } | { ok: false, reason: string }` — reason の文言: 空「名前を入れてください。」、長すぎ「名前は20文字までです。」、重複「同じ名前のラベルがあります。」
  - `createLabel(store, id: string, name: string, now: number) -> Store`（`created = u = now`）
  - `renameLabel(store, id, name, now) -> Store`、`deleteLabel(store, id, now) -> Store`（`deleted: true, u: now`）
  - `setLabel(store, labelId, itemKey, on: boolean, now) -> Store`
  - `activeLabels(store) -> Array<{ id, name, created }>` — 削除していないラベルを `created` の昇順（同じなら id 順）
  - `labelsOf(store, itemKey) -> string[]` — その項目に付いている、削除していないラベル ID（`activeLabels` の順）
  - `itemsOf(store, labelId) -> Array<{ key: string, u: number }>` — `on: true` の項目を `u` の降順。ラベルが削除済み・存在しなければ `[]`
  - `resolveLastUsed(store, lastId) -> string | null` — `lastId` が有効ならそれ、無ければ `created` が最大の有効ラベル、それも無ければ `null`
